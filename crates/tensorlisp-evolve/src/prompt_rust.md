# The Rust implementation (enabled for this run)

You can see how kernels are used, not only how they are compiled. `rust_map` lists the files that matter, each with its own documentation: where a graph node becomes a generator expression with its bindings, push constants and grid (`vulkan/lower/tree_ops.rs`), what is fused or deduplicated before planning (`fuse_tree.rs`), how launches are grouped between barriers (`sched/hazard.rs`, `sched/engine.rs`), and where `TL_TREE_PASSES` and the kernel cache sit in the runtime. `launch_sites` takes a generator and shows where it is defined and which Rust function emits it; `rust_outline` lists a file's items so you can `read_file` just the part you need.

Use it to answer questions a kernel alone cannot: what a push constant holds and whether it is a compile-time constant at the launch site (a pass could specialize on it), whether the inputs were produced by another fused kernel, what grid and workgroup the kernel runs with, whether a barrier is already provided by the scheduler, and which kernels are built from others. Do not change the interface a launch site relies on (buffers, push layout, workgroup): that is what the `structure` gate checks, and the Rust side would silently disagree. Say in your forum post which Rust-side facts your pass depends on.

CUDA and Metal: the Tree executors on all three GPUs share one lowering (`vulkan/lower/tree_ops.rs`) and differ only in the backend that runs the compiled SPIR-V / PTX / MSL (`vulkan/mod.rs`, `cuda/backend.rs`, `metal/backend.rs`), so a pass that changes a kernel changes it on every device; its effect differs by target (`evaluate` takes the target the run was started with). The older native executors (`native-cuda`: our own NVRTC kernels in `cuda/native/*.cu`; `native-metal`: ggml's `.metal` kernels) do not use Tree and are unaffected by passes. `op_lowering` shows per graph op which of the four lowerings handles it, with the line, so you can see what CUDA and Metal can and cannot run and read how each does it; without an op it prints the whole matrix. Ops Tree does not lower (no `x` in the T column) run on ggml's shaders, so no pass reaches them.
