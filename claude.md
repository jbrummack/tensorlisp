## layout
Cargo workspace, see README.md (also documents the program format). `crates/chez` embeds Chez (bindgen'd scheme.h + C shim for its macros, boot files via include_bytes!). `crates/ggml-sys` builds vendored ggml (`vendor/ggml`) with cc only (no cmake), backend features (`platform-backends` default = metal on macOS), bindgen into OUT_DIR. `crates/ggml-codegen` generates the Scheme FFI (raw foreign-procedures, implicit-ctx `ggml-*` ops, enum constants, symbol table). `crates/tensorlisp` is the runtime (Model::load/run, Scheme on a dedicated thread, library in src/scheme/core.ss); `crates/tensorlisp-cli` is `tl` (inspect/convert/pack/check/run/compare/quantize, all with --json). `crates/kernels` (`tensorlisp-kernels`) is the ggml-independent kernel launcher: Metal implemented (runtime-compiled MSL, vendored mistral.rs paged-attention kernels, feature `ggml` shares ggml-Metal's device/queue/tensor buffers via `crates/ggml-sys/csrc/metal_interop.*`); CUDA implemented behind feature `cuda` (Driver API + NVRTC, both `dlopen`'d via `libloading` so the crate builds without a toolkit; same vendored paged-attention kernels, NVRTC-compiled instead of AOT; tested on an RTX 3080, see docs/design/kernel-launcher.md). It also holds the native Metal executor (`Device::Native`, `--device native`: ggml cgraph -> IR -> arena plan -> recorded dispatch list over ggml's own .metal kernels, matmul policy in Scheme `src/scheme/native.ss`; TIPSv2 runs on it; ops it lacks fail at compile time by name), see docs/design/kernel-launcher.md; `crates/importers` has onnx/coreml readers; `experiments/` holds archived attempts (hand-written lisps, first gguf loader).
ggml asserts are caught: at graph build via a Chez foreign-callable abort handler (Chez unwinds), on the calling thread in Rust via setjmp wrappers in `crates/ggml-sys/csrc/guard.c`; worker-thread asserts still abort.
ChezScheme is the submodule `vendor/ChezScheme`, built with `scripts/build-chez.sh` into `vendor/chez` (gitignored).

## plan
done: runtime (Model::load/run, taps, graph info), assert recovery, `tl` CLI, first real port `ports/tipsv2` (TIPSv2 B/14 text + vision encoders, match PyTorch; reference env is a CPU-only torch nix flake, clean with `nix store gc`). Stdlib: R6RS libraries `(tl tensor|nn|attn|vision|util)` in crates/tensorlisp/src/scheme/stdlib/, loaded at boot; programs `(import (tl nn))` at the top which binds canonical prefixes (`nn:linear`, `attn:sdpa`, ...), only (tl ...) importable; reference in docs/stdlib.md, tests in tests/stdlib.rs; all ports use it. Porting patterns/pitfalls: docs/porting-notes.md. Preprocessing: `../autopro` (sibling repo, path dependency) does images/audio/text (Pillow-exact resize, native SentencePiece, tokenizer.json, Whisper mels), validated against HF via its reference/ flake; exposed to programs through `(preprocess ...)` + host functions (crates/tensorlisp/src/host.rs, handles to Rust values) and GGUF assets `TL_ASSET.<name>`. Postprocessing: autopro `detect` (torchvision NMS, Ultralytics detector NMS, letterbox) and `cluster` (sklearn DBSCAN, Accelerate sgemm via feature `platform-blas`), validated via `nix develop .#post` in its reference/; programs use `(postprocess (output-or-raw-name ...) ... (results ...))`, per example (outputs split on their first dim), Rust `Model::infer`, `tl run` shows results (--no-post). The chez crate restores signal handlers Chez installs. `tl quantize` is graph-aware (needs -i shapes). Generated FFI passes C bool params as `boolean` (Chez stdbool stack-arg bug on arm64 macOS). Multiple entries per program: `(model name ...)` (unnamed = main; default = main or first), per-entry scheduler+graph, `(pipeline name ([raw kind]..) ...)` runs entries from Scheme via `(run entry [in arr]..)` (host.rs tl_host_run_* -> model.rs run_program_entry; with_scheme runs inline when already on the Scheme thread), results can be text; CLI `--entry`, quantize over all entries (`ENTRY:NAME=`), convert `--replace-prefix`. Second port: `ports/t5gemma2` (T5Gemma 2 270M-270M, image captioning + text generation, greedy, KV cache via state tensors; weights gated, HF_TOKEN in .env). State: `(define-state name type dims..)` + `(state name)` + `(effect t)` (expands into the graph immediately; the graph is created before the body), allocated on the primary device at load, `Model::reset_state`. `tl convert --offset GLOB=V` (t5gemma2 needs +1 on RMSNorm weights). Third port: `ports/yolo11` (YOLO11n detector, Ultralytics reference flake; `(device)` returns cpu/gpu so programs pick kernels: im2col convs on Metal, direct convs on CPU). `tl run -i` skips a postprocess that needs raw inputs. Fourth port: `ports/ppocrv6` (PP-OCRv6 medium det + rec in one GGUF, entries `det`/`rec`, pipelines `ocr`/`recognize`; weights exported by reference.py with BNs folded and short `det.`/`rec.` names; matches transformers 5.17). OCR host functions (`text-boxes`, `text-boxes-order`, `image-crop-text`, `ctc-greedy`, `vocabulary*`) come from autopro `ocr`, which ports OpenCV's findContours/minAreaRect/fillPoly/warpPerspective bit-exactly (fixtures: `make_ocr_fixtures.py` in autopro's `.#post` shell). Stdlib convs: non-square kernels, `(h w)` strides/padding, banded im2col beyond 256 MiB, `nn:conv-transpose2d` (matmul when kernel = stride). CUDA backend: `crates/ggml-sys` feature `cuda` (forwarded from `tensorlisp`/`tensorlisp-cli`), vendors `vendor/ggml/src/ggml-cuda` (upstream `ggml-org/ggml` v0.20.1, matches this repo's vendored version exactly) and compiles it with the `cc` crate's `.cuda(true)` (nvcc), same source selection as upstream's CMakeLists.txt glob. Needs `CUDA_PATH` (Windows) or `CUDA_HOME`/`CUDA_ROOT` (Linux); GPU arch from `GGML_CUDA_ARCH` or auto-detected via `nvidia-smi`, default sm_86. `ggml_sys::HAS_CUDA` gates tests the same way `HAS_METAL` does; `model.rs`'s device selection is backend-agnostic so no runtime changes were needed. `crates/kernels`'s CUDA launcher (separate from the ggml-sys CUDA backend above: this one is the kernel-launcher/paged-attention layer, parallel to Metal's native executor) ports vLLM's paged-attention/reshape_and_cache/gather_kv_cache CUDA kernels (via mistral.rs) to NVRTC: vendored sources are trimmed to device-only code (host launcher math reimplemented in Rust, matching `metal::paged_attn`) and flattened with a hand-written prelude (fixed-width typedefs, `FLT_MAX`, no-op `assert`) since NVRTC has no host libc to resolve `<stdint.h>` etc. against; `copy_blocks` is hand-written, not vendored, matching the Metal port's single-cache-pair simplification over upstream's multi-layer version. Tested (`cargo test -p tensorlisp-kernels --features cuda`) on an RTX 3080. `crates/tensorlisp-aot` (CoreML/ANE, added alongside the Metal `kernels` work) needs sibling repos `../../coreml-rs` and `../../cg-leafnode` beyond `../autopro`; neither is present on the Windows box, and both are macOS-only anyway, so that crate doesn't build there (temporarily drop it from the root `[workspace] members` to build/test anything else on Windows; don't commit that removal).
Native CUDA executor (`--device native` with feature `native-cuda`, or `cuda`): crates/kernels `cuda/{exec,lower}.rs` + `cuda/native/*.cu` (own NVRTC kernels, uniform `(Op, src0..3, dst)` signature, Rust-side matmul policy), shared graph conversion in `crates/tensorlisp/src/native_ir.rs`, device glue `native_metal.rs`/`native_cuda.rs` selected in lib.rs; `native_device` cfg from build.rs; matches ggml CPU on TIPSv2/T5Gemma2/YOLO11n/PP-OCRv6 (tests/native*.rs). Scheduler (docs/design/scheduler.md): `crates/kernels/src/sched` is the backend-neutral async dispatch layer (kernel blobs + signatures, hazard analysis -> barrier groups, `Space::{Model,Session,Step}` memory with size-class pools, `Engine::submit` -> `Ticket`), `crates/kernels/src/vulkan` its first backend (feature `vulkan`, `ash` with the loader dlopen'd, SPIR-V blobs; feature `wgsl` translates WGSL via naga since there is no glslc), `crates/kernels/src/cuda/backend.rs` is the CUDA `Backend`; `tests/common` is a backend-generic conformance suite run by `tests/{vulkan,cuda}_sched.rs` on the RTX 3080 (Vulkan under the validation layer; `tests/vulkan_validation.rs` proves a missing barrier is caught, which needs `syncval_shader_accesses_heuristic`, set via VK_EXT_layer_settings). ggml's own Vulkan shaders are vendored at `vendor/ggml/src/ggml-vulkan` (upstream v0.20.1) and dispatched as SPIR-V blobs by `tests/ggml_vulkan.rs` (add/sub/mul/div, copy, scale, rms_norm, mat-vec f32/Q4_0 match the CPU): `sched/spirv.rs` reflects signatures from the SPIR-V, `vulkan/glsl.rs` compiles GLSL with `glslc` or, absent that, glslang unpacked in the gitignored `vendor/glslang` (the Vulkan SDK with glslc is installed at `C:\VulkanSDK`; `scripts/build-ggml-vulkan-shaders.sh` compiles all 1976 ggml Vulkan variants into `target/ggml-vulkan/spv`, loaded by `vulkan::ggml::SpvLibrary`). ggml's own Vulkan backend builds with `--features vulkan` on `ggml-sys`/`tensorlisp`/`tensorlisp-cli` (needs the SDK headers and `scripts/build-ggml-vulkan-shaders.sh` run once; `ggml_sys::HAS_VULKAN`): TIPSv2 text, YOLO11n, T5Gemma2 and Gemma 4 E2B (q8_0 and f16) run and match CPU/HF on `--device gpu` (docs/design/scheduler.md, "Models on ggml's Vulkan backend"). Native Vulkan executor (`--device native` with feature `native-vulkan` on `tensorlisp`/`tensorlisp-cli`; no ggml-vulkan or SDK needed to build, but `scripts/build-ggml-vulkan-shaders.sh` must have produced the `.spv` library): `crates/kernels/src/vulkan/{lower,exec}.rs` lower the IR to ggml's precompiled shaders (host logic ported from ggml-vulkan.cpp) and run it on the sched `Engine`, glue in `crates/tensorlisp/src/native_vulkan.rs`; Gemma 4 E2B q8_0 (identical to the HF reference), T5Gemma2 (generate and caption), TIPSv2 text/vision and YOLO11n run on it and `crates/tensorlisp/tests/native.rs` passes 8/9 (reflect pad missing); not lowered: PAD_REFLECT_1D, mrope/vision rope, bf16 matrix matmul, sinks, antialiased upscale (see docs/design/scheduler.md, "The native Vulkan executor"). `vulkan/fuse.rs` fuses rms_norm+mul(+rope) before planning (`TL_NATIVE_NOFUSE`, `TL_NATIVE_TRACE`). The model caches one compiled native program per input shape. Tree (docs/design/tree.md): kernel language compiled to SPIR-V by Scheme libraries `(tl tree)` / `(tl tree spirv)` (`stdlib/tree*.ss`, loaded at boot); `tests/tree_vulkan.rs` checks softmax/matmul kernels (`tests/tree_kernels.ss`) against CPU and times them against ggml's shaders. `TL_VULKAN_PROFILE=1` prints per-kernel GPU time (timestamps). `TL_NATIVE_TREE=1|only` (native Vulkan executor) lowers nodes to Tree kernels from `stdlib/tree_kernels.ss` via `vulkan/lower/tree_ops.rs` (TIPSv2 text, Gemma 4 E2B q8_0 and T5Gemma2 f16 run entirely on them under `=only`, tokens/text matching the references; Gemma's step is 7.9 ms against 6.25 ms on ggml's shaders; `tests/tree_library.rs` compiles and validates every generator). Tree also has a PTX target (`stdlib/tree_ptx.ss`, loaded by the CUDA backend through the driver JIT, `tests/tree_ptx.rs`) and a dp4a q8_0 mat-vec (int8 activations, on by default under Tree, `TL_TREE_DOT=0` for f32), learned from ggml-cuda's PTX (`scripts/ggml-cuda-ptx.bat`; docs/design/tree.md). Tree-to-Tree passes live in `stdlib/tree_opt.ss` (`(tl tree opt)`: fold, licm, cse, dce, `register-pass!`; `TL_TREE_PASSES`); they change little on Vulkan/PTX (the drivers do the same), the wins are graph fusion before planning (`vulkan/fuse_tree.rs`: node CSE, `FUSED_EW` elementwise regions, `FUSED_ROW` norm/add/scale chains, int8 producer outputs `q8_out`/`q8_side`; `TL_TREE_NOFUSE=1` off), split-KV flash attention (`k:flash-attn-part`/`combine`), and engine changes (replayed command buffers, reads folded into the submission, level-scheduled groups, no arena reuse in small arenas; docs/design/scheduler.md). Gemma 4 E2B decode step on the RTX 3080: 6.1 ms (Tree) against 7.2 ms (ggml's shaders on the same engine; 9.1 ms before the engine work), `tests/tree_gemma.rs`; with exact f32 activations (`TL_TREE_DOT=0`) Tree is 7.7 ms, slower than ggml. `TL_NATIVE_DUMP=<file>` dumps compiled node lists. Tensor cores: Tree has cooperative-matrix forms (`cmat`, `cm-load`, `cm-muladd`, `cm-store`; SPIR-V only) and `k:matmul-cm`, used for products with >= 16 columns when the device has f16 16x16x16 subgroup coopmat (`TL_TREE_NOCM=1` off); TIPSv2 text encoder 9.98 to 4.78 ms (ggml shaders 5.53). Tree on the native CUDA device: feature `native-cuda-tree` (`src/native_cuda_tree.rs`) runs the Vulkan executor's lowering over PTX through the sched CUDA backend (`vulkan::exec::Executor<B>`, `cuda/tree.rs`, `TreeKernels::from_blobs`); TIPSv2 text, PP-OCRv6, T5Gemma2 and Gemma 4 E2B q8_0 (single-sequence decode 131 tokens/s against 36 on the NVRTC executor) run on it, paged attention included (same Tree kernels as Vulkan). Also `norm_rope` (FUSED_NR) fusion on by default and `gate_up` (FUSED_GU, `TL_TREE_GU=1`) opt-in, neither moves Gemma's step. Tree also has an MSL target (`stdlib/tree_msl.ss`) and a Metal `sched::Backend` (`crates/kernels/src/metal/{backend,tree}.rs`): feature `native-metal-tree` runs the Vulkan executor's lowering over MSL on the native Metal device (all of tests/native.rs and native_tips.rs match the CPU backend, including conv/pool/pad/upscale kernels and q4/q5/q4_K/q6_K dequantization added as shared Tree kernels; YOLO11n 9.7 ms vs 15.4 ms on the ggml-kernel executor; docs/design/tree.md, "MSL target"). The Metal and CUDA executors are not ported onto the engine yet; the v2 program format split, per-session state, yielding pipelines and `tl serve` are designed but not started. Later: TL_BIN binary programs, C bindings, rust preprocessors (autoprocessors), vulkan backend (needs the Vulkan SDK + a glslc shader-codegen build step this project doesn't have yet).
RPC server: `crates/tensorlisp-serve` (`tl-serve`, Cap'n Proto, schema in `schema/tensorlisp.capnp`, needs the `capnp` tool at build time; docs/design/serve.md): install models by streaming a GGUF into a content-addressed store, `describe`, `run` entries on tensors (f32/f16/bf16 in and out), start pipelines; streaming works for pipelines (`[xs stream]` parameters, `(stream-recv xs)`, `(emit 'name v)`, `Run.input`/`Run.output`; pipelines are coroutines that leave the Scheme thread while they wait for a chunk or run an entry, see docs/design/serve.md); per-session state works (`Model.session()`, `ModelState`: separate `(define-state ...)` tensors per client; zero-copy blocks on native devices, copy-on-switch on ggml backends); `Session.fork` copies a session; `(client-call ...)`/`(client-sample ...)` in pipelines call the client's `Callbacks` (custom samplers); `SamplerConfig` and `Session.getState/setState` are in the schema but not implemented. `tl-serve --connect ADDR` is reverse mode: the worker dials a scheduler, offers its Server on that connection and calls `Scheduler.register` (redials when dropped). `crates/tensorlisp/src/kernel_cache.rs` persists Tree compiler output (`TL_KERNEL_CACHE`, default ~/.cache/tensorlisp/kernels, `off` disables). Flash attention with at least 16 queries uses `k:flash-attn-cm` (tensor cores, two passes over the keys, Apple GPUs; T5Gemma2's vision tower 58 s -> 5 s, docs/design/tree.md); `TL_TREE_NOFACM=1` keeps the scalar kernel. Tested on a real model (T5Gemma2 q8_0, tests/real_model.rs, `ports/t5gemma2/rpc.ss` adds the demo pipelines). Features mirror the CLI's (`native-metal-tree`, ...).
GGUF keys: TL_TXT (utf8 program), TL_BIN (binary), TL_VER (u32 version).
