## layout
Cargo workspace, see README.md (also documents the program format). `crates/chez` embeds Chez (bindgen'd scheme.h + C shim for its macros, boot files via include_bytes!). `crates/ggml-sys` builds vendored ggml (`vendor/ggml`) with cc only (no cmake), backend features (`platform-backends` default = metal on macOS), bindgen into OUT_DIR. `crates/ggml-codegen` generates the Scheme FFI (raw foreign-procedures, implicit-ctx `ggml-*` ops, enum constants, symbol table). `crates/tensorlisp` is the runtime (Model::load/run, Scheme on a dedicated thread, library in src/scheme/core.ss); `crates/tensorlisp-cli` is `tl` (inspect/convert/pack/check/run/compare/quantize, all with --json). `crates/kernels` (`tensorlisp-kernels`) is the ggml-independent kernel launcher: Metal implemented (runtime-compiled MSL, vendored mistral.rs paged-attention kernels, feature `ggml` shares ggml-Metal's device/queue/tensor buffers via `crates/ggml-sys/csrc/metal_interop.*`), CUDA planned, see docs/design/kernel-launcher.md; `crates/importers` has onnx/coreml readers; `experiments/` holds archived attempts (hand-written lisps, first gguf loader).
ggml asserts are caught: at graph build via a Chez foreign-callable abort handler (Chez unwinds), on the calling thread in Rust via setjmp wrappers in `crates/ggml-sys/csrc/guard.c`; worker-thread asserts still abort.
ChezScheme is the submodule `vendor/ChezScheme`, built with `scripts/build-chez.sh` into `vendor/chez` (gitignored).

## plan
done: runtime (Model::load/run, taps, graph info), assert recovery, `tl` CLI, first real port `ports/tipsv2` (TIPSv2 B/14 text + vision encoders, match PyTorch; reference env is a CPU-only torch nix flake, clean with `nix store gc`). Stdlib: R6RS libraries `(tl tensor|nn|attn|vision|util)` in crates/tensorlisp/src/scheme/stdlib/, loaded at boot; programs `(import (tl nn))` at the top which binds canonical prefixes (`nn:linear`, `attn:sdpa`, ...), only (tl ...) importable; reference in docs/stdlib.md, tests in tests/stdlib.rs; all ports use it. Porting patterns/pitfalls: docs/porting-notes.md. Preprocessing: `../autopro` (sibling repo, path dependency) does images/audio/text (Pillow-exact resize, native SentencePiece, tokenizer.json, Whisper mels), validated against HF via its reference/ flake; exposed to programs through `(preprocess ...)` + host functions (crates/tensorlisp/src/host.rs, handles to Rust values) and GGUF assets `TL_ASSET.<name>`. Postprocessing: autopro `detect` (torchvision NMS, Ultralytics detector NMS, letterbox) and `cluster` (sklearn DBSCAN, Accelerate sgemm via feature `platform-blas`), validated via `nix develop .#post` in its reference/; programs use `(postprocess (output-or-raw-name ...) ... (results ...))`, per example (outputs split on their first dim), Rust `Model::infer`, `tl run` shows results (--no-post). The chez crate restores signal handlers Chez installs. `tl quantize` is graph-aware (needs -i shapes). Generated FFI passes C bool params as `boolean` (Chez stdbool stack-arg bug on arm64 macOS). Multiple entries per program: `(model name ...)` (unnamed = main; default = main or first), per-entry scheduler+graph, `(pipeline name ([raw kind]..) ...)` runs entries from Scheme via `(run entry [in arr]..)` (host.rs tl_host_run_* -> model.rs run_program_entry; with_scheme runs inline when already on the Scheme thread), results can be text; CLI `--entry`, quantize over all entries (`ENTRY:NAME=`), convert `--replace-prefix`. Second port: `ports/t5gemma2` (T5Gemma 2 270M-270M, image captioning + text generation, greedy, KV cache via state tensors; weights gated, HF_TOKEN in .env). State: `(define-state name type dims..)` + `(state name)` + `(effect t)` (expands into the graph immediately; the graph is created before the body), allocated on the primary device at load, `Model::reset_state`. `tl convert --offset GLOB=V` (t5gemma2 needs +1 on RMSNorm weights). Third port: `ports/yolo11` (YOLO11n detector, Ultralytics reference flake; `(device)` returns cpu/gpu so programs pick kernels: im2col convs on Metal, direct convs on CPU). `tl run -i` skips a postprocess that needs raw inputs. Fourth port: `ports/ppocrv6` (PP-OCRv6 medium det + rec in one GGUF, entries `det`/`rec`, pipelines `ocr`/`recognize`; weights exported by reference.py with BNs folded and short `det.`/`rec.` names; matches transformers 5.17). OCR host functions (`text-boxes`, `text-boxes-order`, `image-crop-text`, `ctc-greedy`, `vocabulary*`) come from autopro `ocr`, which ports OpenCV's findContours/minAreaRect/fillPoly/warpPerspective bit-exactly (fixtures: `make_ocr_fixtures.py` in autopro's `.#post` shell). Stdlib convs: non-square kernels, `(h w)` strides/padding, banded im2col beyond 256 MiB, `nn:conv-transpose2d` (matmul when kernel = stride). CUDA backend: `crates/ggml-sys` feature `cuda` (forwarded from `tensorlisp`/`tensorlisp-cli`), vendors `vendor/ggml/src/ggml-cuda` (upstream `ggml-org/ggml` v0.20.1, matches this repo's vendored version exactly) and compiles it with the `cc` crate's `.cuda(true)` (nvcc), same source selection as upstream's CMakeLists.txt glob. Needs `CUDA_PATH` (Windows) or `CUDA_HOME`/`CUDA_ROOT` (Linux); GPU arch from `GGML_CUDA_ARCH` or auto-detected via `nvidia-smi`, default sm_86. `ggml_sys::HAS_CUDA` gates tests the same way `HAS_METAL` does; `model.rs`'s device selection is backend-agnostic so no runtime changes were needed. Later: TL_BIN binary programs, C bindings, rust preprocessors (autoprocessors), vulkan backend (needs the Vulkan SDK + a glslc shader-codegen build step this project doesn't have yet).
GGUF keys: TL_TXT (utf8 program), TL_BIN (binary), TL_VER (u32 version).
